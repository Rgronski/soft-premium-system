# MS-032.2 Historical Archive Numbering And Overlap Policy

This document defines the MS-032.2 policy for historical archive numbering, overlapping source reports, pre-formal origins, supporting evidence, and future promotion into development logs or session summaries.

This policy does not rewrite historical facts. It records handling rules for archived evidence after MS-032.0 and MS-032.1, while preserving unresolved identity, numbering, date, and overlap questions for Product Owner decisions.

## Session Identity

| Field | Value |
| --- | --- |
| Previous Session ID | 096 |
| Current Session ID | 097 |
| Next Session ID | UNKNOWN |

## Scope

Product Owner archive labels are archive/order labels unless a source proves a formal SPS OS Session ID.

Pre-formal origin sources remain separate from formal SPS OS sessions. A source report may support later formal reconstruction, but it is not automatically a formal development log, formal session summary, milestone closure, commit proof, push proof, or SSOT state proof.

Current Product Milestone remains `NONE / Product Owner decision required`.

## Archive Numbering Rules

| Label or file signal | Treatment |
| --- | --- |
| `0000001 Foundation Day` | PRIMARY pre-formal origin source, not a formal Session ID. |
| Duplicate-label `0001` candidates | Separate source reports until Product Owner decides otherwise. |
| `0002` | Supporting evidence only, not proof of Project Onboarding Capability implementation. |
| `0003` through `00022` | Archive-labeled source reports, not automatically formal session summaries. |
| `UNKNOWN_DATE` / `UNKNOWN` prefix files | Valid evidence with unresolved identity and/or date. |

## Overlap Rules

- An overlap candidate is not duplicate proof.
- Do not merge reports based on title similarity alone.
- Do not delete or replace source reports during overlap review.
- Prefer additive cross-reference notes in future index or policy artifacts over editing archived source bodies.
- Do not normalize internal labels, dates, headings, warnings, `UNKNOWN` values, or caveats inside archived report bodies during overlap review.

## Promotion Rules

- A source report can become the basis for a development log or session summary only after Product Owner decision.
- `FULL` source completeness does not automatically mean formal summary eligibility.
- `PARTIAL` source completeness or supporting-evidence-only classification must not be promoted alone into a formal session summary.
- Do not infer missing dates, formal session numbers, milestone completion, implementation status, commit hashes, push state, branch state, merge state, final repository state, or SSOT state.
- Do not treat archive filename order as proof of historical chronology unless the source report itself proves chronology.
- Do not use overlap review to rewrite source report bodies.

## MS-032.3 Readiness Gate

Before creating formal backfill artifacts in MS-032.3 or later work, Product Owner must choose:

- Exact source report or source reports to use.
- Target artifact type: development log, session summary, index supplement, policy supplement, or another explicitly approved artifact.
- Handling for unresolved `UNKNOWN` values.
- Handling for duplicate-label or topic-overlap candidates.
- Whether supporting evidence is sufficient for the chosen artifact type.

If any of those decisions are missing, the safe action is to keep the material as source-report evidence only.

## Recommended Next Step

Product Owner chooses the first candidate group for MS-032.3 formal backfill preparation, or asks for an overlap review table before any formal backfill artifact is created.
