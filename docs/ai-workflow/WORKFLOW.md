# AI Workflow

## Full Workflow

1. Project Context Loader
2. Project Integrity Check
3. Diagnosis
4. Review
5. Scope Approval
6. Chief Architect -> Codex Handoff
7. Codex Implementation
8. Chief Architect Verification
9. User Acceptance
10. Commit
11. Push
12. Documentation Update
13. Documentation Review
14. Milestone Close
15. Session Close

## Meaning Of The Flow

Project Context Loader establishes the required project context.

Project Integrity Check verifies that documentation and repository state are ready for work.

Diagnosis and Review happen before implementation.

Codex implements only after scope approval and handoff.

Documentation is updated only after implementation and repository actions are confirmed.

## Integrated Workbench Direction

AI Workspace is the transitional surface for the target integrated SPS OS project workbench.

The intended workbench keeps Chief Architect conversation, Konduktor guidance, and Project Brain context on the left, with a Codex Window on the right.

The current workflow remains manual: handoff is copied to external Codex, Codex returns a report, and Product Owner brings the report back for Chief Architect review.

Future stages may add local report handling, read-only execution status/history, a controlled Codex runner contract, and a real execution bridge only after separate approval.

Cross-project operational memory is a separate future contract candidate and is not part of the current workflow implementation.

## Important Distinction

Milestone Close is not the same as Session Close.

Milestone Close means the approved scope for the milestone is complete, verified, documented, and ready for repository closure.

Session Close means the current collaboration session is finished and the next session can resume safely from updated documentation.
